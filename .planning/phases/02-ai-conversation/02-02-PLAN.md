    === PART C: Conversation Service Updates (src/services/conversation.ts) ===
    Add to existing exports:

    - `endSession(userId: string): Promise<{sessionId: string, stats: {messageCount: number, correctionCount: number}} | null>`:
      1. Find active session in cache where session.userId === userId
      2. If not found, return null
      3. Get thread from cache, set session status to "ended" in-memory FIRST (before archiving — per RESEARCH.md Pitfall 2, prevents race condition)
      4. Update Session in DB: set status="ended", endedAt=new Date(), messageCount, correctionCount
      5. Archive thread: await thread.setArchived(true) (D-07)
      6. Remove from activeSessions cache
      7. Return session stats

    - `getSessionSummary(userId: string): Promise<{messageCount: number, correctionCount: number, summary: string, duration: string} | null>`:
      1. Find active session for userId
      2. Load session from DB with message count
      3. Calculate duration (now - createdAt)
      4. Return formatted stats

    - `rehydrateSessions(client: Client): Promise<void>`:
      1. Query prisma.session.findMany({ where: { status: "active" }, include: { messages: { orderBy: { createdAt: "desc" }, take: 10 } } })
      2. For each active session data:
         a. Try to fetch Discord thread via client.channels.fetch(sessionData.discordThreadId)
         b. If thread exists and is a ThreadChannel:
            - Register in activeSessions cache
            - Unarchive if archived: if (thread.archived) await thread.setArchived(false)
         c. If thread doesn't exist or fetch fails:
            - Set session status to "ended" in DB (the thread was deleted)
         d. If thread exists but is not a thread channel (unexpected): log warning, set status to "ended"
      3. Log `Rehydrated ${count} active sessions`

    === PART D: Summarization Service (src/services/summarizer.ts) ===
    Per D-13/D-14/D-15, CONV-06:

    - `shouldSummarize(contextMessages: {role: string, content: string}[], turnCount: number): boolean`:

    - `triggerSummarization(sessionId: string, thread: ThreadChannel): Promise<void>`:
      1. Load full message history: prisma.message.findMany({ where: { sessionId }, orderBy: { createdAt: "asc" } })
      2. Build summarization prompt from prompts/conversation/summarize.md template, passing all messages as context
      3. Call GPT-4o-mini (model: "gpt-4o-mini", max_tokens: 500) with summarization prompt
      4. Parse response: prepend timestamp `[${new Date().toISOString()}]`
      5. Update Session.summary field in DB with new summary (D-15)
      6. Prune old messages: keep last 10 verbatim (for context freshness), delete rest from Message table
      7. Apply the research recommendation: summarize only when BOTH totalTokens > 80K AND turnCount > 5

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → Bot | Command invocations (/end, /summary) — untrusted input via Discord |
| Bot → Redis/PostgreSQL | Session state persistence during shutdown and rehydration |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-02 | Tampering | endSession (conversation.ts) | medium | mitigate | Set session status to "ended" in-memory BEFORE archiving thread. Message handler checks in-memory status first — prevents race where a message arrives between /end and archive. |
| T-2-03 | Denial of Service | shutdown (index.ts) | high | mitigate | isShuttingDown guard flag prevents re-entrant shutdown. Save sessions BEFORE client.destroy() (per Pitfall 5 — prevents Prisma disconnect race). 10-second force-exit timeout. |
| T-2-04 | Spoofing | rehydrateSessions (conversation.ts) | low | accept | Threads are verified via Discord API (client.channels.fetch) during rehydration. If fetch fails, session is ended. Only already-authenticated sessions are rehydrated from DB. |
| T-2-05 | Information Disclosure | summarizer.ts | low | accept | Summarization prompt includes full conversation history sent to OpenAI API. The user is aware messages are processed by AI. No PII expected in language learning context. |
</threat_model>
