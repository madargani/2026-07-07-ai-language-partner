    ### src/commands/review.ts

    **Imports** (follow reviewed patterns — do NOT re-read source files):
    - `ActionRowBuilder, ButtonBuilder, ButtonStyle, ComponentType, EmbedBuilder, MessageFlags, SlashCommandBuilder` from "discord.js"
    - `prisma` from "../lib/prisma.js"
    - `getDueItems, rateItem` from "../services/fsrs.js"
    - `type Command` from "../types/discord.js"

    **Command definition:**
    ```typescript
    export const command: Command = {
      data: new SlashCommandBuilder()
        .setName("review")
        .setDescription("Review due vocabulary and grammar items with spaced repetition"),
      async execute(interaction) { ... },
    };
    ```

    **execute() implementation:**

    1. `await interaction.deferReply({ flags: MessageFlags.Ephemeral })` (follow setup.ts pattern)
    2. Fetch user: `prisma.user.findUnique({ where: { discordId: interaction.user.id } })`
    3. Guard: if `!user?.configured`, reply with "Please run `/setup` first." and return (same pattern as add-item.ts)
    4. Fetch due items: `getDueItems(user.id)` (REVW-01)
    5. If `items.length === 0`, reply with completion message and return
    6. Call `showReviewCard(interaction, items, 0, user.targetLanguage, user.nativeLanguage)` to start the flow

    **showReviewCard() implementation:**

    ```typescript
    async function showReviewCard(
      interaction: ChatInputCommandInteraction,
      items: ReviewItem[],
      index: number,
      targetLang: string,
      nativeLang: string,
    ): Promise<void>
    ```

    1. **Completion check** (REVW-05): if `index >= items.length`, show celebration embed and return
       - Green embed (#2ecc71) with title "🎉 Review Complete!" and "You reviewed all X items."

    2. **Build the embed:**
       - Color: purple (#9b59b6)
       - Title: "Review X of Y"
       - Fields: "Item" (source + type), "Prompt Type" (from rotatePrompts)
       - Footer: "Rate how well you remembered this item"
       - Per RESEARCH recommendation: template-based prompts for v1 (no extra LLM call)

    3. **Prompt type rotation** (REVW-02): use `index % 3` to cycle through:
       - 0 = "use-in-sentence": `"Use '{source}' in a {targetLang} sentence."`
       - 1 = "fill-in-blank": `"Complete: The word '{source}' best fits which blank?"`
       - 2 = "native-translation": `"How do you say '{source}' in {nativeLang}?"`

    4. **Build buttons** (REVW-03):
       - `againBtn`: customId `review_again_{item.id}`, label "Again", Danger style
       - `hardBtn`: customId `review_hard_{item.id}`, label "Hard", Danger style
       - `goodBtn`: customId `review_good_{item.id}`, label "Good", Success style
       - `easyBtn`: customId `review_easy_{item.id}`, label "Easy", Success style
       - `exitBtn`: customId `review_exit`, label "Exit", Secondary style
       - Two ActionRows: first with 4 rating buttons, second with Exit button

    5. **Send embed + buttons:**
       ```typescript
       await interaction.editReply({ embeds: [embed], components: [ratingRow, exitRow] });
       ```

    6. **Wait for button click** (follow setup.ts `awaitMessageComponent` pattern):
       ```typescript
       const buttonInteraction = await interaction.channel!.awaitMessageComponent({
         componentType: ComponentType.Button,
         filter: (i) =>
           i.user.id === interaction.user.id &&
           (i.customId.startsWith("review_") || i.customId === "review_exit"),
         time: 120_000,
       });
       ```

    7. **Handle button press:**
       - `await buttonInteraction.deferUpdate()`
       - If `review_exit`: show yellow embed (#f39c12) "📚 Review Session Ended — You reviewed X of Y items." and return
       - Map button prefix to FSRS rating (REVW-03):
         - `review_again` → 1 (Again maps to FSRS rating 1)
         - `review_hard` → 2 (Hard maps to FSRS rating 2)
         - `review_good` → 3 (Good maps to FSRS rating 3)
         - `review_easy` → 4 (Easy maps to FSRS rating 4)
         - Extract prefix by stripping `_{item.id}` suffix from customId
       - Call `rateItem({ itemId: item.id, rating })` (REVW-04)
       - Call `showReviewCard(interaction, items, index + 1, targetLang, nativeLang)` (REVW-05)

    8. **Timeout handling** (follow setup.ts pattern):
       ```typescript
       catch (error) {
         if (error instanceof Error && error.message.includes("time")) {
           await interaction.editReply({ embeds: [timeoutEmbed], components: [] });
           return;
         }
         throw error;
       }
       ```
       - Red embed (#e74c3c): "⏰ Review Session Expired — Run /review again to continue."

    **Design notes (from RESEARCH.md Consensus patterns):**
    - Custom ID format: `review_{rating}_{itemId}` — encodes rating and item ID for per-item matching
    - Recursive `showReviewCard` — no external state tracking, each card calls itself with `index + 1`
    - Collector timeout of 2 min — auto-ends stale sessions (under the 15-min Discord interaction limit)
    - Template-based prompts for v1 — no extra LLM calls per card (RESEARCH recommendation)
    - Exit button shows progress summary, not celebration (partial completion)

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Spoofing | review.ts — button customId forgery | low | mitigate | CustomId format `review_{rating}_{itemId}` encodes both the rating action and item ID. The button filter in `awaitMessageComponent` checks `i.user.id === interaction.user.id` — only the user who initiated /review can interact. The item ID in customId is validated because `rateItem()` does a `findUnique` lookup and throws if item doesn't exist. No direct injection surface — buttons are created server-side with static labels and known customIds. |
| T-04-07 | Information Disclosure | review.ts — unauthorized item access | medium | mitigate | `getDueItems(userId)` filters by the caller's Discord userId (looked up via `prisma.user.findUnique`). `rateItem()` validates the item exists but does NOT verify ownership in v1. If user A somehow obtains user B's itemId, they could rate it. For v1 this is acceptably low-risk because itemIds are UUIDs (unguessable) and the only exposure is through the user's own review flow. **Mitigation:** Add `where: { id: itemId, userId }` to `rateItem`'s findUnique in a future phase. |
| T-04-08 | Tampering | review.ts — rateItem race condition | low | accept | If two reviews run simultaneously for the same item (unlikely with ephemeral responses), the second rateItem would overwrite the first. In practice, /review is ephemeral per-user, so concurrent reviews for the same item cannot happen from the same user. Accept for v1. |
</threat_model>
