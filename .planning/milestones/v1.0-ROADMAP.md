# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-07-21
**Phases:** 1-5
**Total Plans:** 8

## Overview

An AI-driven language learning Discord bot that combines freeform conversational practice with spaced repetition. Users chat naturally in their target language, receive contextual corrections, and reinforce vocabulary/grammar through structured FSRS-based review sessions — all through Discord slash commands.

## Phases

### Phase 1: Foundation & Setup

**Goal**: Bot connects to Discord, accepts slash commands, persists user configuration, and deploys via Docker Compose
**Depends on**: Nothing (first phase)
**Plans**: 1 plan

Plans:
- [x] 01-01-PLAN.md — Walking Skeleton (Discord commands, Docker Compose, graceful shutdown)

**Details:**
- Docker Compose with 3 services (postgres:17, redis:7, bot) with healthchecks
- Discord bot with /ping, /setup (two-step select menu), /new commands
- Prisma User model with ISO 639-1 language codes, Zod env validation
- Graceful shutdown with isShuttingDown guard, SIGINT/SIGTERM handlers
- 28 tests, 6 decisions honored

### Phase 2: AI Conversation

**Goal**: Users can hold natural target-language conversations with the bot, receiving contextual corrections without breaking conversational flow
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:
- [x] 02-01-PLAN.md — Core conversation loop: /new, message handler, GPT-4o-mini responses with corrections
- [x] 02-02-PLAN.md — Session lifecycle: /end, /summary, summarization, rehydration, graceful shutdown

**Details:**
- OpenAI GPT-4o-mini conversation with delimiter-based correction parsing
- Correction budget: max 2 major errors corrected per message
- Embed builder: orange with corrections or green with "No errors found!"
- Session + Message Prisma models with indexes
- Progressive summarization (tiktoken, 80K token threshold + turnCount > 5)
- Session rehydration on bot restart from PostgreSQL
- 28 tests, 18 decisions honored

### Phase 3: FSRS Spaced Repetition Bank

**Goal**: Vocabulary and grammar items are stored with complete FSRS scheduling fields and managed by the ts-fsrs algorithm
**Depends on**: Phase 1
**Plans**: 1 plan

Plans:
- [x] 03-01-PLAN.md — FSRS service layer with createItem, rateItem, getDueItems, getItem

**Details:**
- ReviewItem model with full FSRS-5 fields (stability, difficulty, state, due, elapsedDays, scheduledDays, reps, lapses)
- ts-fsrs integration: grade type (1|2|3|4) for scheduler.next()
- 14-day interval cap for items < 3 months old
- Cold start handled with ts-fsrs built-in default parameters
- /add-item slash command with source, type (vocabulary/grammar), optional language
- 37 tests, 11 decisions honored

### Phase 4: Extraction & Review

**Goal**: As a language learner, I want to automatically extract vocabulary from my conversations into FSRS cards and review due cards with structured prompts
**Depends on**: Phases 2, 3
**Plans**: 2 plans

Plans:
- [x] 04-01-PLAN.md — Extraction pipeline: BullMQ/Redis queue, GPT-4o-mini worker with structured output, post-conversation enqueue hook, dedup, graceful shutdown
- [x] 04-02-PLAN.md — Review command: /review with FSRS rating buttons (Again/Hard/Good/Easy), template-based prompts, recursive card flow, timeout handling

**Details:**
- BullMQ/Redis queue with exponential backoff, concurrency=1, dead-letter queue
- GPT-4o-mini extraction with Zod structured output (detectedItems, typosIgnored)
- Semantic filtering distinguishing cognitive mistakes from mechanical typos
- Code-switching detection auto-extracts native terms as new FSRS items
- 3 prompt types: use-in-sentence, fill-in-blank, native-translation
- Ephemeral replies, 2-min idle timeout, completion celebration
- 55 tests (9 extraction + 9 review + 37 prior), 10/10 UAT passed

### Phase 5: Session Summary

**Goal**: Users get actionable post-session insights including top strengths, vocabulary expansion metrics, and review queue health
**Depends on**: Phases 2, 4
**Plans**: 2 plans

Plans:
- [x] 05-01-PLAN.md — Data infrastructure: ReviewItem.sessionId FK, SessionSummary model, getQueueHealth(), extraction sessionId pass-through
- [x] 05-02-PLAN.md — Summary enhancement: LLM strength analysis, enhanced embed, SessionSummary persistence

**Details:**
- SessionSummary Prisma model (1:1 FK to Session, onDelete: Cascade)
- ReviewItem.sessionId nullable FK for session tracking
- getQueueHealth() FSRS service function counting items due in 24h
- Strength analysis via gpt-4o-mini at /summary time
- Enhanced embed: Messages, Corrections, Duration, Top Strengths, New Items, Queue Health
- SessionSummary persistence via Prisma $transaction
- Thread archive AFTER database transaction (Pitfall 5 mitigation)
- 62 tests total, 7/7 UAT passed

## Milestone Summary

### Decimal Phases

None — all phases were integer-numbered.

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Prisma 6 (not 7) | Avoid radical WebAssembly migration risk | ✓ Good |
| GPT-4o-mini for conversation | Cost-effective, good enough quality | ✓ Good |
| Delimiter-based correction format | Simplest implementation, no extra API cost | ✓ Good |
| ts-fsrs defaults for cold start | No custom constants needed | ✓ Good |
| BullMQ/Redis for extraction | Persistence, retries, monitoring | ✓ Good |
| Template-based review prompts | No LLM call per card (cost + latency) | ✓ Good |
| gpt-4o-mini for strength analysis | Follows summarizer.ts pattern, predictable cost | ✓ Good |
| Thread archive AFTER $transaction | Critical data before cosmetic cleanup | ✓ Good |

### Issues Resolved

- Prisma back-relation fields required for schema validation (auto-fixed)
